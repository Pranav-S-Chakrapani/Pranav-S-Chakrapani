# Animated card system

This repo's `README.md` is a stack of `<img>` tags pointing at SVGs in
`cards/`, each generated by `scripts/generate_cards.py`. Nothing in
`cards/` is hand-edited -- it's all build output.

## Layout

| File | What it is |
|---|---|
| `cards/hero.svg` | Name, one-line bio, portrait |
| `cards/tile-1.svg` .. `tile-3.svg` | Three linked tiles, placed side by side at `width="32.5%"` |
| `cards/chart.svg` | Contributions/month bar chart + current streak, active-day rate, busiest weekday |
| `cards/repo-<slug>.svg` | One card per featured repo in `data/config.json` |
| `cards/graph.svg` | Daily contribution heatmap, tinted in the brand purple |

## Editing content

Everything text/color/link related lives in `data/config.json` -- name,
tagline, portrait URL, the three tiles, and the list of featured repos.
Add or remove a repo there and re-run the generator; a matching
`repo-<slug>.svg` appears or disappears. If you add/remove a tile or
repo, update the `<img>` list in `README.md` to match.

## How the animation works, and why it's limited to this

Since every card is served as an `<img>`, there's no JavaScript runtime
available at all -- only what a plain image can animate:

- **CSS `@keyframes`** in an inline `<style>` block (fades, pop-ins,
  growing bars) -- declared once in `svgkit.base_style()` / embedded per
  card, with each element's `animation-delay` staggered by
  `svgkit.stagger()` so the page reads top to bottom as the cards load.
- **SMIL `<animate>`** elements for the contribution-graph cells (each
  cell animates its own `fill` from the empty shade to its final shade,
  staggered left to right).
- **`prefers-reduced-motion`**: `svgkit.reduced_motion_css()` adds
  `* { animation: none !important; }` under that media query, which
  overrides every inline `style="animation: ..."` above (an `!important`
  stylesheet rule beats a plain inline style). The graph's SMIL
  `<animate>` elements use `fill="freeze"`, so once the override stops
  new frames from being generated, GitHub's static render shows each
  cell already settled on its final value -- nothing animates for people
  who've asked for reduced motion.

## Fonts

`svgkit.subset_font_b64()` runs `pyftsubset` against
`fonts/FiraCode-Regular.woff2` / `fonts/FiraCode-Bold.woff2`, keeping
only the glyphs a given card's own text actually uses, then inlines the
result as a `data:font/woff;base64,...` URI in that card's `@font-face`.
Nothing is fetched at render time -- each SVG is fully self-contained,
which is required for it to render correctly as a bare `<img>` src
outside a browser's normal page context.

## Rendering a static preview before you push

Cards normally play their intro animation every time the `<img>` loads.
To render just the final, settled frame (e.g. to screenshot the result
before committing):

```bash
STATIC=1 python scripts/generate_cards.py
```

This skips the `<style>` keyframes and SMIL `<animate>` elements
entirely and draws every element already in its resting state -- so
what you see is exactly what the animation settles into, without having
to wait for it or capture video.

Run it again without `STATIC` to restore the animated version before
you commit.

## Keeping the data fresh

`data/contributions.json` holds daily contribution counts and is what
`generate_cards.py` reads for the monthly chart, streak, active-day
rate, busiest weekday, and the heatmap. `.github/workflows/update-cards.yml`
runs on a daily schedule (and on every push that touches `data/config.json`
or `scripts/`): it calls `scripts/fetch_contributions.py` to pull fresh
data from GitHub's GraphQL API, re-runs `generate_cards.py`, and commits
`cards/` + `data/contributions.json` if anything changed.

`fetch_contributions.py` needs a token with `read:user` scope -- the
default `GITHUB_TOKEN` Actions provides can't read your contribution
calendar. Create a classic Personal Access Token with that scope and
add it as a repository secret named `CONTRIB_READ_TOKEN`.

For local testing without hitting the API, `scripts/make_sample_data.py`
writes plausible fake data to `data/contributions.json`.

## Regenerating by hand

```bash
pip install fonttools brotli
python scripts/make_sample_data.py   # only if data/contributions.json doesn't exist yet
python scripts/generate_cards.py
```
